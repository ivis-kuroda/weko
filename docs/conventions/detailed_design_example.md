## 設計書作成にあたっての注意事項・記載粒度ガイド

> このセクションは設計書を書く執筆者向けの案内です。本サンプルを記入する際の指針であり、実際の設計書（テンプレートから作成したもの）には転記不要です。
> 設計書の枠組み（章構成・プレースホルダー）は [`detailed_design_template.md`](detailed_design_template.md) を複製して使い、各欄は**本サンプルと同等の粒度**で埋めてください。

### 設計書を書くときの注意事項

- **エラーメッセージ文言は完成形で書く**: エラーハンドリング表のメッセージは `"Failed to send registration email to {user.email}: {e}"` のように変数埋め込みを含む完成形で記載し、コードにそのまま使える状態にする。「適切なメッセージ」等の曖昧表現は禁止（各関数のエラーハンドリング表を参照）。
- **設定値はキー名・デフォルト値・配置ファイルを明記する**: 設定キーごとに「キー名・デフォルト値・型・用途・連結／生成ルール・配置ファイル」をすべて埋める。環境変数経由・他キーとの連結がある場合は生成方式（取得式）まで書く（セクション 3 を参照）。
- **曖昧表現を使わない**: 値の取得元・条件分岐の閾値・固定文字列の扱いなど、実装者が迷いうる箇所は具体的に書く。「適切に」「必要に応じて」「既存処理」「同様に」だけで済ませない。
- **処理ステップにマーカーを付ける**: 各処理ステップに「（既存処理）」または「★新規追加」を付け、既存／新規を区別する（各関数の処理仕様を参照）。既存の処理内容そのものを変更する場合は「（既存処理変更）」を付け、変更前の処理内容・変更後の処理内容・変更理由を必ず明記する。
- **コードスニペットは実装判断ポイントのみに添付する**: 関数全体のコードを貼らない。迷いうる判断（例: 例外をキャッチするか）に必要な最小限のスニペットのみ添える。それ以外は擬似コード（自然言語）で書く。
- **非機能要件の根拠は参照ポインタに留める**: 設定値仕様の「非機能要件由来の根拠」列には基本設計書 5.x への参照（例: 「基本設計書 5.1」）のみを書き、根拠の実体は基本設計書に残す。

### 記載粒度の目安（主要セクション別）

- **1. 変更ファイル一覧**: 新規・修正・削除するファイルを過不足なく 1 ファイル 1 行で列挙。変更概要は「何をするファイルか／何を追加するか」を 1 句で。備考は DB マイグレーション等の不可逆操作がある場合のみ記入。
- **2. 関数仕様（1 関数あたり）**:
  - **目的・概要**: 1〜3 文で「何をするか」と「どう実装するか」の結論を記載。設計判断の根拠は基本設計書 7 を参照させる。
  - **引数 / 戻り値**: 引数は型ヒント記法と「None の可否」を全行記入。戻り値は型に加え「成功時」「失敗時／例外時」を分けて具体値・キー名まで明記。
  - **処理仕様**: 箇条書きで **3〜6 ステップ程度**を目安にする。各ステップに「（既存処理）」「★新規追加」または「（既存処理変更）」のマーカーを付ける。「（既存処理変更）」を付ける場合は変更前の処理内容・変更後の処理内容・変更理由を必ず明記する。
  - **実装判断ポイント / 実装上の注意事項**: 曖昧になりうる分岐には**最低 1 件**記載する。実装上の注意事項は「注意点＋どう対処するか」をセットで 2〜4 件を目安に挙げる。
  - **エラーハンドリング表**: 想定エラー条件ごとに 1 行。「条件・例外クラス・ErrorType／コード・メッセージ文言（完成形）」を**必ず全列埋める**。
- **3. 設定値仕様**: 設定キーごとに各列を必ず明記する。環境変数経由・他キーとの連結がある場合は取得式まで書く。
- **4. 実装チェックリスト**: 「実装した」ではなく「動作を確認した」粒度まで分解し、確認コマンド例を添える。

### 粒度を揃えるための原則

- 同一セクション内の各項目（各関数の仕様、各設定キーなど）は、互いに**同程度の詳細度**で書くこと。ある関数だけ極端に詳しい／薄い状態を避け、複数メンバーが分担しても粒度が揃うようにする。

1. `app` コンテキストが存在することを前提とする。Flask アプリケーションコンテキスト内で呼び出されることを保証するのは呼び出し元（`/app/routes/auth.py`）の責務。 **（既存処理）**

2. `app.config` から以下のキーを取得する。 **（既存処理）**  
   - `MAIL_DEFAULT_SENDER`: 送信元アドレス
   - `MAIL_SERVER`: SMTPホスト
   
   > **実装判断ポイント**: `MAIL_SERVER` が `None` の場合はメール送信をスキップし、WARNINGログを出力してそのまま `return` する。例外は送出しない。
   > ```python
   > if not current_app.config.get("MAIL_SERVER"):
   >     current_app.logger.warning("MAIL_SERVER is not configured. Skipping email.")
   >     return
   > ```

3. `render_template("email/registration_complete.html", user=user)` を呼び出してメール本文を生成する。 **★新規追加**  
   テンプレートに渡す変数は `user` のみ。テンプレート内では `user.email` と `user.display_name` を参照する。

4. `flask_mail.Message` オブジェクトを生成する。 **★新規追加**  
   ```python
   msg = Message(
       subject="【サービス名】アカウント登録が完了しました",
       sender=current_app.config["MAIL_DEFAULT_SENDER"],
       recipients=[user.email],
       html=html_body,
   )
   ```
   > **実装判断ポイント**: `subject` の文字列は上記のとおり固定文字列とする。`f-string` でサービス名を動的に挿入しないこと。

5. `mail.send(msg)` を呼び出してメールを送信する。 **★新規追加**

6. ステップ 3〜5 全体を `try/except Exception as e` で囲む。例外発生時は `current_app.logger.error(f"Failed to send registration email to {user.email}: {e}")` を記録し、`return` する。 **★新規追加**

#### 実装上の注意事項

<!-- 
  キー名の誤記注意、既存コードとの衝突、型変換が必要な箇所、
  ライブラリの非直感的な挙動など、実装者が見落としやすいポイントを記載する。
  「注意」だけでなく「どう対処するか」も記載する。
-->

- `flask_mail.Message` のキーワード引数は `recipient` ではなく **`recipients`**（複数形）。誤記するとTypeErrorになる。
- `mail` オブジェクトは `/app/__init__.py` で `mail = Mail(app)` として初期化済み。`from app import mail` でインポートして使用する。新たに `Mail()` インスタンスを生成しないこと。
- `user.display_name` は `None` の場合がある（任意項目のため）。テンプレート内では `{{ user.display_name or user.email }}` のようにフォールバックを設定すること。
- Flask-Mail の `send()` はSMTP接続に失敗すると `smtplib.SMTPException` を送出する。`Exception` でキャッチすれば包含されるため、個別にキャッチする必要はない。

   > **実装判断ポイント**: `send_registration_email` は内部で例外をキャッチするため、戻り値チェックや `try/except` の追加は不要。
3. 既存のAPIレスポンスをそのまま返す。 **（既存処理）**
4. メールアドレスの重複チェック処理を変更する。 **（既存処理変更）**
   - **変更前の処理内容**（`/app/routes/auth.py` L45-48）:
     ```python
     existing_user = User.query.filter_by(email=email).first()
     if existing_user:
         return jsonify({"error": "Email already registered"}), 400
     ```
     大文字・小文字を区別した完全一致でのみ重複判定していた。
   - **変更後の処理内容**: メールアドレスを小文字に正規化してから重複チェックする。
     ```python
     existing_user = User.query.filter(func.lower(User.email) == email.lower()).first()
     if existing_user:
         return jsonify({"error": "Email already registered"}), 400
     ```
   - **変更理由**: `User@Example.com` と `user@example.com` のように大文字・小文字のみ異なるメールアドレスで二重登録が発生する不具合が確認されたため（基本設計書 3.1 不具合対応事項を参照）。
